## 1. 개발 배경 — 왜 이 프로젝트를 하는가

### 1.1 문제 상황
- **연하장애(삼킴 장애)는 흔하고 위험하다.** 뇌졸중 환자의 상당수(문헌에 따라 약 40~70%)가 급성기에 연하장애를 겪으며, 신경계 질환·구강암 수술 후·노화에서도 널리 나타난다. 삼킴이 약해지면 음식물이 기도로 넘어가(흡인) **흡인성 폐렴**으로 이어질 수 있고, 이는 고령 환자 재입원과 사망의 주요 원인 중 하나다.
- **먹는 것이 곧 회복이다.** 삼킴이 어려우면 영양·수분 섭취가 줄어 체력과 면역이 떨어지고, 재활 전체의 회복 속도가 늦어진다. "잘 먹는 것"은 컨디션 회복의 핵심 조건이다.
- **병원 치료를 지속하기 어렵다.** 연하 재활은 매일 반복해야 효과가 나지만, 퇴원 후에는 거리·비용·보호자 부담 때문에 병원에서 꾸준히 치료받기 힘들다.
- **집에서 하는 운동은 지루하다.** 입 벌리기·입술 다물기·혀 내밀기 같은 구강 운동은 단순 반복이라 동기가 쉽게 떨어지고, 혼자서는 "제대로 하고 있는지"도 알 수 없어 중도 포기가 많다.

### 1.2 해결 아이디어
> 집에서, 웹캠 하나로, **재활 동작 자체가 게임 조작이 되는** 놀이형 훈련.

- 얼굴 인식으로 입·입술·볼·혀·턱 움직임을, 마이크로 기침을 실시간 판정해 캐릭터를 움직인다.
- 동작을 크게·정확하게 할수록 더 빨리·더 화려하게 보상한다("동작 크기 = 보상").
- 실패·게임오버가 없고, 개인 기준값을 매번 재서 **그 사람 능력에 맞춘 판정**을 한다.
- 매 판의 반복 횟수·유지 시간·최대 동작 크기가 기록되어 회복 흐름을 볼 수 있다.

## 2. 목적과 목표

### 2.1 목적
1. 연하 재활에 필요한 **구강·안면·기침 운동을 집에서 반복 수행**하도록 돕는다.
2. 게임 요소로 **지속 참여(adherence)**를 높인다.
3. 동작 인식으로 **올바른 자세를 유도**하고 기록을 남겨 재활 진행을 스스로 확인하게 한다.

### 2.2 이번 기한(2026-09-21)까지의 목표
- Unity 버전 **10개 스테이지 전부 플레이 가능**
- 개인 기준값 저장 · 판마다 기록 · 중간 이탈 부분 기록(공통 마무리)
- PC 빌드 1종 + 전체 통합 테스트

## 4. 근거 — 임상적·기술적 배경

### 4.1 임상 근거
- **구강 운동 훈련**(입 벌리기, 입술 폐쇄, 혀 운동, 볼 부풀리기)은 연하 관련 근육의 근력·가동범위·협응을 개선하는 표준 재활 요소다.
- **수의적 기침 훈련**은 기도 방어의 마지막 방어선이다. 연하장애 환자는 기침 반사가 약해 의도적으로 기침을 연습하는 것이 실제 치료 목표다(Stage 9).
- **성문 위 삼킴법(supraglottic swallow)** — 입에 받기 → 머금기 → 숨 참기 → 턱 당겨 삼키기 → 기침. 흡인 위험 환자에게 실제로 가르치는 안전 삼킴 순서이며, Stage 10은 이 순서를 그대로 게임화했다(순서 변경·랜덤 금지).
- **턱 당기기(chin tuck)**는 아래로 숙일 때만 인정한다. 고개 젖힘은 사레 위험을 높이는 반대 자세이므로 잘못된 동작을 학습시키지 않도록 설계했다.
- **개인화 판정의 필요**: 웹 실측에서 고정 기준(예: 입술 다물기 0.40)이 사용자에게 도달 불가(최대 0.25)임을 확인 → 모든 판정은 연습에서 잰 개인 기준값의 비율로 결정.

### 4.2 게임화·재활 지속 근거
- 재활 운동의 효과는 **반복 빈도**에 비례하나 가정 운동의 순응도는 낮은 것으로 알려져 있다. 즉각 피드백·보상·진행 표시는 순응도를 높이는 대표적 요소다.
- 본 프로젝트는 "지시문 표현 방식이 판정 성공률에 직접 영향"(웹 Stage 7 실측: 안내 문구만 바꿔 인식 0.00 → +0.25)을 확인해, **정확한 임상 지시문 = 좋은 인식률**이라는 설계 원칙을 도출했다.

### 4.3 기술적 근거
- 웹 버전(JavaScript + MediaPipe)에서 10개 스테이지 전부 **사용자 실측·테스트 통과**, 판정 임계값·연출·규칙이 검증 완료.
- Unity 이식은 검증된 수치를 그대로 옮기는 작업이므로 판정 로직의 재실험 부담이 낮다.

## 5. 기대 효과

| 구분 | 기대 효과 |
|---|---|
| 환자 | 집에서 매일 부담 없이 반복 · 동작 크기가 보상으로 이어져 **더 크게, 더 정확하게** 하려는 동기 · 기록으로 회복 흐름 확인 |
| 보호자 | 운동 여부·횟수를 확인 가능 · 병원 방문 부담 감소 |
| 치료사 | 가정 과제 처방 도구 · 세션별 반복 횟수·최대 동작값·좌우 비대칭 데이터로 상담 근거 확보 |
| 사회 | 흡인성 폐렴 예방 → 재입원 감소 · 저비용 가정 재활 접근성 확대 |

⚠ 본 소프트웨어는 의료기기가 아니며 **진단·판정 표현을 하지 않는다.** 기록 화면은 숫자만 보여주고 해석은 전문가에게 맡긴다.

### 6.2 공통 시스템
- **연습(캘리브레이션) → 게임** 2단계 흐름: 연습에서 개인 기준값을 재고 "바로 시작" 개방
- **완료 카드**: 반복 횟수·유지 시간·최대 동작값 + 누적("지금까지 N판")
- **중간 이탈 부분 기록**: 도중에 나가도 운동량은 남김(실패 없음 원칙)
- **GUI**: 타이틀·인트로·로그인(별명) 씬, 카드형 스테이지 선택(Scroll-Snap), 스테이지 미리보기 팝업

### 6.3 데이터·기록 (웹 완성 → Unity 향후)
- 환자는 **별명만** 저장(개인정보 미수집) · 세션(판)별 기록 · 식사 단계 설문 · 오늘 컨디션
- 대시보드: 회복 추이(동작별 하루 최고값) · 활동 캘린더 · 게임별 기록 · 좌우 균형(횟수+거리) · 설정

## 7. 적용 기술

| 영역 | 기술 |
|---|---|
| 엔진 | Unity 6000.0.58f2 · 2D Built-In Render Pipeline · C# |
| 얼굴 인식 | MediaPipe Face Landmarker (homuler MediaPipeUnityPlugin v0.16.3) — 52개 블렌드셰이프 + 478개 랜드마크 + 얼굴 변환 행렬(head pitch) |
| 혀 인식 | 입술 안쪽 마스킹 + HSV 색 인식 픽셀 카운트(TongueScanner) — 블렌드셰이프로는 잡히지 않는 혀 동작 판정 |
| 소리 인식 | Unity Microphone API → RMS → dB(0~100) · 피크 홀드 · 개인 캘리브레이션 |
| UI | uGUI · Simple Scroll-Snap · Easter GUI 에셋 · CanvasGroup |
| 에셋 제작 | Gemini(캐릭터/배경 이미지) · SVG 배경 자체 제작 |
| 데이터 | (웹) Supabase PostgreSQL + RLS · (Unity 향후) 로컬 JSON 큐 → REST |
| 검증 | 웹 프로토타입(JavaScript/MediaPipe tasks-vision)에서 판정값 실측 → Unity 이식 |
| 협업 | Git/GitHub · 단계별 사용자 테스트 사이클 · HANDOFF 문서 기반 인수인계 |

**기술적 특징**
1. **하이브리드 판정**: 블렌드셰이프(표정) + 랜드마크 기하(볼 너비, 입 위치) + 픽셀 색 인식(혀) + 오디오(기침) + 머리 자세(턱)를 스테이지에 맞게 조합.
2. **히스테리시스 이중 임계값**: 진입/해제선 분리로 값 떨림에 의한 오판정 제거.
3. **실측 기반 임계값**: 모든 판정 수치는 사용자 실측으로 확정(예: mouthPucker는 평소값이 높아 배제, 혀 밝기 하한 50→90).
4. **스레드 안전 처리**: MediaPipe 콜백 스레드에서 필요한 값만 추출해 메인 스레드로 전달.

## 10. 한계 및 고려사항
- **호흡을 카메라로 직접 잴 수 없다** — Stage 10의 "숨 참기"는 안내만 하고 바로 삼키기로 넘어간다(임상적으로도 숨을 참은 상태에서 곧바로 삼키는 것이 기법에 맞음). 포트폴리오에 정직하게 기록.
- **조명·카메라 환경 의존** — 혀 색 인식은 어두운 방에서 약해질 수 있어 밝기 하한 조정 여지를 둠.
- **의료기기 아님** — 진단·치료 효과를 주장하지 않으며, 전문가 지도 하의 보조 도구로 위치.
- **개인정보 최소화** — 실명·생년월일·연락처 미수집, 별명만 사용, 웹캠 영상은 저장하지 않음.
