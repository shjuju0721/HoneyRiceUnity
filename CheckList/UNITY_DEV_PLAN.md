## 1. 개발 원칙 (웹 버전에서 확정, Unity에서도 동일)

1. **실패/게임오버 없음** — 시간 제한·감점 없음. 본인 속도로 끝까지 간다.
2. **개인화(baseline)** — 고정 임계값은 사용자에게 도달 불가함이 실측으로 증명됨(줄다리기 0.40 → 실측 최대 0.25). 연습에서 잰 값의 비율로 판정.
3. **동작 크기 = 보상** — 크게 할수록 더 빨리·더 화려하게.
4. **관대형 판정 + 이중 임계값(히스테리시스)** — 진입선과 해제선을 분리해 떨림 방지.
5. **판정·진단 표현 금지** — 기록 화면은 숫자만. "좋아졌다/나빠졌다" 단정 금지.
6. **안내 문구가 곧 인식률** — 임상 지시문을 정확히("입을 아~ 벌린 채 혀끝을 입꼬리에 콕").
7. **단계별 진행 + 매 단계 사용자 테스트** — 한 번에 다 만들지 않는다.
8. **사용자가 거절한 항목은 다시 제안하지 않는다** (§7 참고).

## 3. 단계별 개발 계획

### Phase 1 — Stage 7 「젤리 분류」 완성 (현재)
**목표**: 좌우 혀 판정 비대칭 해결 → 게임 로직 → 클리어.

| 단계 | 내용 | 웹 레퍼런스 |
|---|---|---|
| 7-1 | 비대칭 원인 진단: 카메라 위에 혀 픽셀 색칠 + 중앙선 오버레이 진단 화면 → 스크린샷으로 확인 | §17.3 (코드 아닌 **동작 자세**부터 의심) |
| 7-2 | 안내 문구 확정: "입을 아~ 벌린 채 혀끝을 왼쪽·오른쪽 입꼬리에 콕" / 기준 재기 "혀끝을 입 한가운데에" | §17.3 |
| 7-3 | `mirrorLR` 방향 실측 확인 (몸 왼쪽 → 화면 "◀ 왼쪽") | §17.2 |
| 7-4 | 연습: 가운데 기준 2초(`lrBase`) · 판정 = balance − lrBase · 4프레임 평균 · ±0.07 | §17.1·17.4 |
| 7-5 | 게임: 세로 통로 배치(위→아래 줄, 맨 아래 판정 대상) · 좌우 접시에 캐릭터 쌓임 · 규칙 상시 표시 · 오답은 도리도리만 · 3연속 같은 종류 금지 | §17.7 |
| 7-6 | 클리어: 폭죽 3초 → 완료 카드 · 좌/우 횟수 + **좌우 최대 거리 따로 기록** | §17.5·§23.5 |
| 7-7 | 다듬기(밀려날 때 회전·쏙 눌림·통통) → 사용자 테스트 | §17.1 |

**Unity 주의**: `balance`가 음수가 정상 — 저장 시 0 이상 클램프 금지.

### Phase 2 — Stage 8 「혀 위아래 러너」
**설계 결정 필요(사용자 확인)**: 웹은 tfjs 모델(up/down/neutral)을 썼다. Unity 선택지:
- (A, 추천) `TongueScanner` 확장 — 입 안 혀 픽셀의 **상하 무게중심**으로 판정(모델 불필요, Stage 6·7 파이프라인 재사용)
- (B) tfjs 모델을 Unity Sentis(ONNX)로 이식 — 좌우 라벨 반전 미해결 이력 있음

| 단계 | 내용 |
|---|---|
| 8-1 | 판정 신호 결정 + 값 표시(진단 화면) |
| 8-2 | 캐릭터·달리기·팻말 앞 멈춤 루프 |
| 8-3 | 장애물 2종: 위=점프(가시 있는 낮은 플랫폼) / 아래=엎드려 통과(내려온 벽돌담) |
| 8-4 | 판정 연결: 방향 0.3초 유지 → 접수 · 오답만 0.9초 잠금 · 멈추면 항상 동작 안내 + 자세 문구 |
| 8-5 | 연습 = 위로 3회 → 아래로 3회 (가운데 스침으로 즉시 해제) |
| 8-6 | 장애물 10개 · 진행 "3 / 10" · 체크무늬 깃발 · 폭죽 · 기록 |
| 8-7 | 다듬기(흙먼지·속도선·깃발 펄럭·나비) → 사용자 테스트 |

**손대지 말 것**: "가운데 확인 후 판정" 재강화(사용자 3차례 피드백으로 뺀 것).

### Phase 3 — Stage 9 「기침 볼링」 (마이크 첫 도입)
**Unity 기술**: `Microphone.Start` + AudioClip 샘플 읽기 → RMS → dB(−60=0, 0=100) · 피크 홀드 1.2초 후 초당 40 하강. 웹의 `autoGainControl=false`에 해당하는 OS 자동 볼륨 조절 여부를 **빌드 대상 기기에서 확인**.

| 단계 | 내용 |
|---|---|
| 9-1 | 마이크 연결 + 볼륨 표시(권한은 표지 버튼에서 카메라 다음 바로) |
| 9-2 | 기침 판정: 짧은 폭발만 인정, 말소리 거절 + **안 셌을 때 이유 표시(유지 확정)** |
| 9-3 | 캘리브레이션: 조용히 2초(소음) → 기침 2회 → 문턱 = 내 기침 50% (& 소음+12) |
| 9-4 | 세기 3단계: 살살(초록)/보통(주황)/세게(금색) · 경계 35%/70% |
| 9-5 | 볼링 연결: 공 굴러감(0.72/0.88/1.05초) → 핀 살살 3~4 랜덤 / 보통 6~7 / 세게 전부 · 몰아주기 ≤2 |
| 9-6 | 3프레임 · 프레임 사이 3초 쉬기 + "준비되면 콜록!" · **총 9회 상한(임상 안전)** · 클리어 |
| 9-7 | 다듬기: 핀 튕겨 날아가기 · 스트라이크 = **부드러운 금색 빛(번쩍 금지)** · 공 구멍 회전 |

### Phase 4 — Stage 10 「떠먹여주기」 (통합, 마지막)
**임상 정체성**: 다섯 동작 순서 = 성문 위 삼킴법(supraglottic swallow). **순서 변경·랜덤 금지, 클리어 안내 카드 생략 금지.**

| 단계 | 내용 |
|---|---|
| 10-1 | `outputFacialTransformationMatrixes` 켜기 → head pitch 산출 (`atan2(−m[9], m[10])`) + 코끝 y. 부호는 **실측**(문서 주석이 서로 반대였음) |
| 10-2 | 다섯 동작 상태 머신 + 하단 5단계 표시줄 |
| 10-3 | 판정 연결: 벌림 0.60 → 다뭄 0.25 → 숨참기 "안내만 1.3초"(세지 않음) → 턱 당김 **아래 방향만**(10° AND 코끝 1%) → 기침(Stage 9 재사용) · 전환 완충 1초(숨참기 뒤만 0.25초) · 6초 막히면 노란 도움말 |
| 10-4 | 숟가락+팔 연출: 오른쪽에서 진입 → 입 앞 → 입에 쏙 → 빈 숟가락 대기 → 퇴장. 숟가락 크기 = 화면 얼굴 높이 기준 |
| 10-5 | 5술 반복 + 죽 줄어드는 그릇 + 피날레(빈 그릇 + 폭죽) + 완료 카드에 **임상 안내 상자** |
| 10-6 | 기준 pitch는 **동작 시키기 전에 미리** 잡기(옛 버그 회피) · 캘리브레이션 단계는 생략 확정 |
| 10-7 | 다듬기(단계 성공 반짝 · 숟가락 계란형/오목/광택) → 사용자 테스트 |

### Phase 6 — 데이터 저장 (Supabase)
웹 스키마를 그대로 쓴다(patients · sessions · surveys). 환자는 **별명만**(실명·생년월일·연락처 수집 안 함).

| 단계 | 내용 |
|---|---|
| 6-1 | 저장 계층 설계: 로컬 JSON 큐 → Supabase REST(UnityWebRequest). 키·주소는 `.gitignore` 제외 파일 |
| 6-2 | 연결 테스트 + 환자 선택 화면(첫 실행 전체 화면, 이후 알약 버튼) |
| 6-3 | 세션 저장(Stage 1) → 나머지 9개 확장 · **저장 실패 재시도 큐** |
| 6-4 | 식사 단계 설문(6단계 식이 + 5단계 음료 점도 + "나중에") · 처음/7일 후/건너뛰면 3일 침묵 |
| 6-5 | 오늘 컨디션(😀🙂😔, 하루 1회, 표지 한 줄) |
| 6-6 | 저장 확인 화면 + 미전송 **빨간 점** |
| 6-7 | 날짜는 **한국 시간(KST)** 경계로 묶기 |

**교훈(반드시)**: 저장 실패는 화면에 안 보인다 → 칸 추가 후 실제 한 판 저장하고 DB 조회로 확인.

## 4. 권장 진행 순서 (참고용, 조정 가능)

```
Phase 1 (Stage 7)  →  Phase 5 일부(기준값·기록 저장 — Stage 8부터는 같이 넣기)
→ Phase 2 (Stage 8) → Phase 3 (Stage 9) → Phase 4 (Stage 10)
→ Phase 5 나머지 → Phase 6 → Phase 7 → Phase 8
```
웹에서는 카드 10개에 약 4주, 데이터+대시보드에 약 3일이 걸렸다. Unity는 에셋 제작이 추가되므로 스테이지당 넉넉히 잡을 것.

## 5. Unity 기술 주의사항 (이 프로젝트에서 이미 확인된 것)

- **Built-In RP 필수** (3D URP로 잘못 시작해 재생성한 이력)
- **MediaPipe 콜백은 별도 스레드** — 콜백 안에서 List 순회 금지, 필요한 float만 뽑아 메인 스레드로
- **블렌드셰이프는 실측 후 채택** — mouthPucker처럼 평소값이 높은 신호는 배제
- **Scroll-Snap 카드에 CanvasGroup 필수**, 팝업은 별도 PopupCanvas(Overlay, Sort 10)
- **한국어 IME 이중 입력** — 입력 필드 Content Type=Custom / Password / Alphanumeric
- 타이머는 실제 시간(`Time.unscaledDeltaTime` 상한 0.25s)으로, 연출은 별도 dt로 분리
- 반올림은 소수 자리 고정이 아니라 **유효숫자 3자리**(볼 값 0.0079 같은 작은 값 보존)

## 6. 임상 결정 (되묻지 말 것)

| 항목 | 확정 내용 |
|---|---|
| 줄다리기 강도 상승 | 상대 씨름 선수가 +1명씩(스펙 원안 뒤집음) |
| 하트 오므림 신호 | mouthFunnel |
| 복어/펭귄 판정 | 볼·입술 둘 다 변화량 60% · 기록은 볼 기준 + 입술 보조 |
| 아이스크림/개구리 | 시간 제한 없음(녹기 = 물방울 연출로 대체) |
| 과일/젤리 | 세로 통로 배치 · 판정선 ±0.07 · 하단 안내 문구 고정 |
| 러너 | "가운데 확인" 제거 · 아래 방향만 완화(0.3 · 4표) |
| 기침 | 연습 2회 · 문턱 50% · 총 9회 상한 · 스트라이크 번쩍 금지 |
| 떠먹여주기 | 순서 고정 · 턱 당기기 아래만 · 숨 참기 세지 않음 · 캘리브레이션 생략 |
| 데이터 | 별명만 · 삭제 금지 · 판정/진단 표현 금지 · 난이도는 저장만 |

## 7. 사용자가 이미 거절한 것 (다시 제안 금지)

- Stage 1 기억 조각 / Stage 3 커서 꼬리·하트 이동·각도 보정 / Stage 5 기록 소수 표기·카드맵 누적
